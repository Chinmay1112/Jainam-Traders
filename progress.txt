## 2. Root Causes Identified & Fixed

### A. TypeScript Compilation (`store-service.ts` & `admin-catalogue-and-inventory.test.ts`)
- **Root Cause**: `createAdminProduct(data, actorId)` required `data` to match `Omit<Product, 'id' | 'createdAt' | 'updatedAt' | 'discountPercentage'>`. Because `Product` has `reservedStock: number`, callers or tests creating a new product without explicitly passing `reservedStock` failed type checks with TS2345.
- **Fix**: Adjusted `createAdminProduct` input type so `reservedStock` is optional:
  `Omit<Product, 'id' | 'createdAt' | 'updatedAt' | 'discountPercentage' | 'reservedStock'> & { reservedStock?: number }`. It defaults safely to 0 when omitted.

### B. Mobile Native Bridge Function Aliases (`capacitor-bridge.ts` & `mobile-native-bridge.test.ts`)
- **Root Cause**: Tests expected named functions `openDialer`, `openWhatsApp`, `openMapDirections`, `shareNative`, and `checkNetworkStatus`, whereas the bridge implemented descriptive names (`openNativeDialer`, `openWhatsAppChat`, `openDirectionsInMaps`, etc.).
- **Fix**: Added explicit named alias exports in [capacitor-bridge.ts](file:///d:/shop%20app/src/lib/native/capacitor-bridge.ts) preserving both API conventions with zero breaking changes.

### C. Type Narrowing In Unit Test (`admin-catalogue-and-inventory.test.ts`)
- **Root Cause**: Vitest unit test defined `const customerRole = 'customer'`, prompting TypeScript to flag `customerRole === 'admin'` as comparing disjoint types.
- **Fix**: Declared type widening `const customerRole: string = 'customer'` so mock auth boundary assertions evaluate properly without TS compiler warning.

### D. Offline Ordering Rule Test (`mobile-native-bridge.test.ts`)
- **Root Cause**: Test variable evaluated literal boolean constant comparison which triggered TS compiler error TS2367.
- **Fix**: Parameterized into an evaluation function `canPlaceOrder(onlineStatus: boolean)` matching the business rule that local reservations require online connectivity.

## 3. Inventory Normalization Engine & Admin Dashboard
- **Engine**: [src/lib/inventory/normalizer.ts](file:///d:/shop%20app/src/lib/inventory/normalizer.ts) guarantees that `totalStock`, `reservedStock`, and `availableStock` are never `NaN`, `undefined`, `null`, or `Infinity`.
- **Formula**: `availableStock = Math.max(0, totalStock - reservedStock)` with integer truncation.
- **Display**: Tested across all inventory views; admin dashboard displays exact quantities, warning badges for low stock, and zero-stock alerts.
- **Customer Privacy**: Customer storefront API continues to show only "Available for pickup" vs "Currently unavailable", never leaking raw stock units to unauthorized clients.
