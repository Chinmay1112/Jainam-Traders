## 2. Issues Discovered, Root Causes & Fixes Applied

### A. Low-Literacy / Village Customer Usability (Part 4)
- **Finding**: Low-literacy customers and elderly shoppers struggled with dense text and English-only menus.
- **Root Cause**: Lack of an accessible assisted mode with spoken confirmations and large tap targets.
- **Fix**: Created `SimpleModeProvider` in `src/lib/context/simple-mode-context.tsx` and `.simple-mode` CSS in `globals.css`. Provides 110% font scaling, minimum 52px tap targets, spoken feedback via `speechSynthesis`, bilingual Hindi/English guidance, and prominent one-touch store calling/WhatsApp buttons.

### B. Voice UX & Natural Phrasing (Part 5 & Part 9)
- **Finding**: Spoken queries like "photo frame dikhao" or "500 rupaye ke andar gift" returned 0 products because continuous string matching failed against colloquial filler words.
- **Root Cause**: Search lacked conversational tokenization and price constraint extraction.
- **Fix**: Implemented `parseSearchQuery` in `src/lib/db/store-service.ts`. It strips common Hindi/English stop words ("dikhao", "chahiye", "hai", "andar", "rupaye") and automatically infers price ceilings (e.g., `500 ke andar` -> `maxPrice = 500`). Mounted `VoiceSearchModal` in `src/components/store/voice-search-modal.tsx` with Web Speech API (`hi-IN` & `en-IN`), visual audio waves, spoken confirmations, and visual fallback suggestion chips.

### C. AI Support Prompt Injection & Credential Leakage (Part 24 & Part 25)
- **Finding**: AI support route lacked defense against adversarial prompts attempting to extract database credentials, system prompts, or private customer records.
- **Root Cause**: Reliance on simple keyword matching without jailbreak rejection.
- **Fix**: Added prompt injection guard at the entry point of `src/app/api/support/ai/route.ts`. Adversarial queries ("ignore instructions", "reveal credentials", "database password", "show all customers") are immediately rejected. Tool outputs never reveal exact stock counts or customer PII.

### D. Accessibility & ARIA Semantics (Part 6)
- **Finding**: Icon-only navigation buttons in header and mobile bottom bar lacked `aria-label` tags.
- **Root Cause**: Buttons relied only on visual icons.
- **Fix**: Added explicit, descriptive `aria-label` attributes across all header action icons, search buttons, clear buttons, and `MobileBottomNav` links.

### E. Android Gradle Build & AGP 8.7.2 Compatibility (Part 32)
- **Finding**: Native Android build initially failed with Java 8 launcher and `androidx.core:core-ktx:1.17.0` requiring Android 36 SDK.
- **Root Cause**: Android Studio was installed with JDK 21 at `C:\Program Files\Android\Android Studio\jbr`, but system defaulted to Java 8. Dynamic transitive dependency resolved `1.17.0` instead of `1.15.0`. Camera plugin required `minSdkVersion = 24`.
- **Fix**:
  1. Configured `org.gradle.java.home=C:/Program Files/Android/Android Studio/jbr` in `android/gradle.properties`.
  2. Pinned `androidx.core:core` and `core-ktx` to `1.15.0` via `resolutionStrategy` in `android/app/build.gradle`.
  3. Increased `minSdkVersion` to `24` in `android/variables.gradle`.
  4. Configured `android/local.properties` pointing to `C:\Users\cjain\AppData\Local\Android\Sdk`.
  5. Successfully compiled `app-debug.apk` in 6m 30s.
